# Подготовка VM к развёртыванию через Ansible

## Узел и доступ

| Параметр | Значение |
| --- | --- |
| VM | `devops-vm`, Ubuntu Server 24.04, VirtualBox |
| Адрес VM в Host-only сети | `192.168.56.103` |
| Доступ с Windows-хоста | `127.0.0.1:2222` через проброс порта VirtualBox |
| SSH-пользователь | `devops` |
| SSH-ключ на управляющем компьютере | `~/.ssh/devops_vm` |
| Docker | установлен; пользователь `devops` входит в группу `docker` |

При проверке практической № 10 подключение к `192.168.56.103:2222` с Windows не отвечало, а проброс `127.0.0.1:2222` работал. Для Ansible с того же Windows-хоста используйте проброс; с другого управляющего узла сначала проверьте доступность адреса VM. Закрытый SSH-ключ в репозиторий не добавлять.

## Проверенный образ

| Параметр | Значение |
| --- | --- |
| Реестр и имя образа | `ghcr.io/gvritia/devops-ci-app` |
| Выбранный тег полного SHA | `529ff9bf1d88c18714edf89364205b977eab9dd8` |
| Полная ссылка | `ghcr.io/gvritia/devops-ci-app:529ff9bf1d88c18714edf89364205b977eab9dd8` |
| Digest опубликованного образа | `sha256:e2e23ec2ad9e1476006143fec07cf9c67bd14f4bb1bed9b94686ead40180a183` |
| Порт в контейнере | `5000/tcp` |
| Проверенный порт VM | `127.0.0.1:5001` для временного контейнера |
| Health endpoint | `GET /health`, ожидаемый ответ `{"status":"ok"}` |

Пакет GHCR публичный: проверенный `docker pull` выполнился без входа в реестр. Если пакет станет приватным, управляющему процессу понадобится доступ на чтение пакета (`read:packages`); токен следует хранить в защищённом хранилище Ansible, а не в inventory, Git или журнале. Для постоянного развёртывания заранее выберите имя контейнера, порт хоста и способ доступа к нему; временное имя `ci-app` и порт `5001` использовались только при проверке.

Проверка на VM по этому SHA дала `{"status":"ok"}` и `uid=999(app)`. Теги SHA и `latest` на момент проверки имели один digest. Для развёртывания используйте выбранный SHA: `latest` может указывать на другой образ после следующей публикации. Образ оставлен на VM, проверочные контейнеры удалены.

## Понятия Ansible для практической № 11

- **Inventory** — список управляемых узлов, групп и параметров подключения. Для этой VM: `ansible_host=127.0.0.1`, `ansible_port=2222`, `ansible_user=devops` при запуске с Windows-хоста.
- **Playbook** — YAML-сценарий, который задаёт требуемое состояние узлов.
- **Task** — отдельное действие в playbook, например загрузка образа по SHA или запуск контейнера.
- **Handler** — задача, запускаемая при уведомлении от изменившей состояние задачи, например перезапуск службы после изменения конфигурации.
- **Role** — повторно используемая структура из tasks, handlers, переменных и шаблонов.
- **Идемпотентность** — повторный запуск с теми же параметрами не должен создавать лишние изменения.

Ansible должен забирать и запускать образ, уже собранный и проверенный CI. Повторная сборка на каждой VM создаёт риск различий между узлами и повторяет работу CI; закреплённый тег SHA позволяет развернуть одну проверенную версию на всех узлах. Для контейнера достаточно описать образ, порт, имя и требуемое состояние, затем проверить `/health`.
